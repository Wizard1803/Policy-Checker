    ```1:55:middleware/auth.js
    const jwt = require('jsonwebtoken');
    const User = require('../models/user.model'); 
    
    const protect = async (req, res, next) => {
        const token = req.cookies.token;
    
        if (!token) {
            req.user = null;
            return next();
        }
    
        try {
            const decoded = jwt.verify(token, process.env.JWT_SECRET);
            const user = await User.findById(decoded.id).select('-password');
    
            if (!user) {
                req.user = null; 
                return next();
            }
    
            req.user = user; 
            next();
        } catch (error) {
            console.error('Token verification failed:', error);
            req.user = null;
            next();
        }
    };
    
    const requireAuth = async (req, res, next) => {
        const token = req.cookies.token;
    
        if (!token) {
            return res.status(401).redirect('/user/login');
        }
    
        try {
            const decoded = jwt.verify(token, process.env.JWT_SECRET);
            const user = await User.findById(decoded.id);
    
            if (!user) {
                return res.status(401).redirect('/user/login');
            }
    
            req.user = user;
            next();
        } catch (error) {
            res.status(401).redirect('/user/login');
        }
    };
    
    module.exports = { protect, requireAuth };
    ```

#### 6 Uploading a policy PDF

- **Front‑end trigger**: on the home page, `Upload Form` opens the upload modal.
  - Modal HTML: `views/partials/modals.ejs`
  - Behavior (open/close): `public/js/home.js`
  - Styling: `public/css/home.css`

- **Back‑end route**: `POST /upload` in `routes/index.routes.js`  
  Protected by `requireAuth` (must be logged in).

  Implementation highlights (see `routes/index.routes.js` for full code):

  - Multer **memory** storage, **15 MB** max, **PDF-only** `fileFilter`.
  - Wrapper around `upload.single('policy')` maps `LIMIT_FILE_SIZE` and other errors to **400** text responses.
  - `sanitizeObjectName` on original filename; Cloudinary `public_id` under `policies/{userId}/…`.
  - `upload_stream` with `resource_type: 'raw'`, `access_mode: 'public'`, per-user `folder`.
  - Saves `fileName`, `fileUrl`, `cloudinaryPublicId`, `cloudinaryVersion`, `uploadedBy`; then **redirect** `/`.

**Flow:**

1. `requireAuth` ensures user is logged in (`req.user` is populated).
2. `multer` parses multipart form and provides `req.file` (in memory).
3. Upload file buffer to Cloudinary as a **raw** resource; store `secure_url` and Cloudinary ids on the `File` document.
4. Redirect back to `/`, where the new file shows in “Recent uploads”.

**Back‑end routes: `POST /files/:fileId/chat` (Multi-Turn RAG) & `POST /check-policy/:fileId` (Single-Turn)**

See `routes/chat.routes.js` and `services/chat.service.js` for handlers. Summary:

- Validates question and user authorization (`uploadedBy` matches `req.user._id`).
- Page-bounded hybrid context assembly (`services/chunk.service.js` using `gemini-embedding-001`) + structured table injection (`services/table.service.js`).
- Dispatches prompt through `services/gemini.client.js` with primary model `gemini-3.6-flash` (fallback `gemini-3.5-flash`).

- Verified citations cross-checked against source chunks (FACTUM anti-hallucination verification).
- Success: JSON response with answer, reasoning, key extracts, and citations.

**Flow:**

1. **Auth & Authorization**: `requireAuth` verifies user session; confirms document ownership (`uploadedBy`).
2. **Hybrid Semantic Retrieval**: In-memory cosine similarity retrieves top-k page-bounded chunks (`gemini-embedding-001`) alongside relevant 2D GFM tables (`services/table.service.js`).
3. **Context Assembly & Re-ranking**: Chunks and tables are injected with Lost-in-the-Middle windowing and multi-turn history (last 3 turns).
4. **Gemini Generation**: Prompt sent to `gemini-3.6-flash` (fallback `gemini-3.5-flash`) with strict citation directives (`[REF-N]`).
5. **FACTUM Attribution**: Backend validates cited excerpts against verbatim source chunk text; verified citations receive `[Verified]` badges with PDF page jump links.
6. **Persistence & Response**: Conversation turn and Message with citation provenance saved to MongoDB and returned to the client.

### End‑to‑end user journey (summary)

1. **New user**:
   - Opens `/user/register`, fills form → `POST /user/register`.
   - User gets stored in MongoDB; app sets `token` cookie and redirects to `/`.

2. **Landing on home**:
   - Browser calls `GET /`.
   - `protect` resolves `req.user`; server loads the user’s files and renders `home.ejs`.

3. **Upload policy**:
   - Clicks "Upload Form" -> modal -> chooses PDF -> submits to `/upload`.
   - Server streams PDF buffer to Cloudinary, creates `File` metadata in MongoDB (`'uploaded'`), and triggers asynchronous background processing.
   - Background worker extracts per-page text, identifies and batches 2D tables, indexes page-bounded chunks with 768d Matryoshka embeddings, and sets status to `'ready'`.

4. **Ask questions & converse**:
   - Clicks "Check Policy" on a file card -> opens conversational chat or inspection modal.
   - User enters policy query -> backend runs in-memory hybrid cosine retrieval across dense chunks and 2D tables, windowing multi-turn context.
   - Gemini generates grounded analysis citing exact references (`[REF-N]`).
   - FACTUM engine validates citations verbatim; UI renders answer with interactive verified page jump anchors.

5. **Compare policies & audit export**:
   - Selects 2–3 policies via floating action dock -> clicks "Compare Policies" (`POST /compare-policies`) for balanced symmetric quota parity comparison.
   - Exports 10-parameter actuarial audit reports with cryptographic SHA-256 provenance hashes via PDFKit (`GET /files/:fileId/export-summary?format=pdf`).

6. **Logout**:
   - User clicks `Logout` -> `GET /user/logout`, token cookie cleared, redirected to login.
